# Патч: стабильный адрес + race condition + скрытый fallback на mimir

## Найденные баги (по логу) и их фиксы

### 1. Адрес Yggdrasil менялся при каждом рестарте
`yggmobile.go`: `Start()` вызывал `config.GenerateConfig()` — генерация
случайного ключа при каждом запуске. Теперь `Start(peers, keyFilePath)`
загружает ed25519-ключ с диска (`<filesDir>/ygg_identity.key`), если он
уже есть, и создаёт его только при самом первом запуске. Self-signed
TLS-сертификат строится вручную через стандартную библиотеку Go
(`crypto/ed25519`, `crypto/x509`, `crypto/tls`) — без зависимости от
внутренней структуры `config.NodeConfig` из yggdrasil-go, чтобы не
рисковать несовпадением версий.

`YggdrasilManager.java`: путь к ключу передаётся как
`appContext.getFilesDir()/ygg_identity.key`.

### 2. Race condition: быстрые тоггл-переключения теряли изменения
Раньше `updatePeers()` проверял `isRunning()` на вызывающем потоке и
тихо выходил, если предыдущий рестарт (асинхронный, в отдельном потоке)
ещё не успел выставить `running=true`. Теперь весь жизненный цикл
(`start`/`updatePeers`) идёт через единый `lifecycleExecutor`
(однопоточный executor) — каждое изменение становится отдельной задачей
в очереди, гарантированно применяется по порядку, ничего не теряется
при быстрых последовательных переключениях.

`stop()` остался синхронным как раньше (для внешних вызовов из
настроек и `XmppConnectionService.onDestroy()`), его тело переименовано
в `stopInternal()`, чтобы очередь `updatePeers()` могла дёргать его
напрямую без повторного логирования.

### 3. Баг с "тремя пирами", который вы заметили
В `startInternal()` была строка:
```java
if (peerList.isEmpty()) peerList = DEFAULT_PEERS;
```
где `DEFAULT_PEERS` — это старый зашитый список из 8 пиров **включая
все 5 mimir-серверов**, оставшийся от прошлой версии до того, как вы их
убрали из UI. При полном отключении всех пиров в списке (`0 enabled`)
код тихо подменял пустой список на этот зашитый — отсюда самостоятельно
оживающие пиры. Константа и подмена полностью удалены: теперь при
0 включённых пирах узел честно стартует без явных пиров (будет искать
только локальные узлы через multicast-обнаружение в той же LAN, если
есть).

## Изменённые файлы
- `yggmobile/yggmobile.go`
- `src/main/java/eu/siacs/conversations/utils/YggdrasilManager.java`

## На что обратить внимание при тесте
- Первый запуск после установки этой версии один раз сгенерирует новый
  identity-файл (адрес ещё раз поменяется один последний раз) — это
  ожидаемо, дальше адрес должен оставаться стабильным при любых
  действиях с пирами.
- При отключении ВСЕХ пиров узел в логе покажет
  `startInternal: 0 peers enabled — starting node with no explicit peers`
  и реально не будет подключён ни к одному внешнему пиру — это
  правильное поведение, раньше оно маскировалось скрытым fallback'ом.
